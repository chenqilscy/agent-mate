## 二、总览：WorkBuddy 是什么

**WorkBuddy 是腾讯出品的全场景 AI 办公智能体桌面工作台**——"说出要求、开始执行任务、交付完整成果"。

与传统 AI 对话的本质区别在于**职责边界**：

| 维度 | 传统 AI 对话 | WorkBuddy |
|---|---|---|
| 产出 | 建议、文案、代码片段 | **可验收的完整成果**（文件、站点、报告、原型） |
| 动作 | 停留在文本层面 | **实际执行**：读写本地文件、跑命令、调外部服务 |
| 任务形态 | 单轮问答 | 多步骤复杂任务：拆解 → 规划 → 执行 → 交付 |
| 连续性 | 会话上下文 | 任务列表持久化、可继续处理、可多任务并行 |

收敛为一句话：**一个以任务为中心、以 Agent Loop 为引擎、以文件系统为锚点、以 MCP 与 Skill 为触手、以三层记忆为延续的全场景 AI 办公工作台**。

## 三、分册摘要

### 📖 分册 01 · 功能清单及功能解读（详见 `01-WorkBuddy功能清单及功能解读.md`）

**功能全景（14 类）**：

| 类别 | 代表功能 |
|---|---|
| 核心对话与任务执行 | 自然语言下达任务、自主规划执行、多任务并行、三种工作模式（Craft/Plan/Ask） |
| 界面三区域 | 侧边栏（任务导航）/ 对话区（人机对话）/ 结果区（成果验收） |
| 文件与代码能力 | 本地文件批量处理、代码生成/审查/重构、陌生代码库理解 |
| 多模态生成 | ImageGen（图）、VideoGen（视频）、3D 模型（消耗积分） |
| 办公云文档 | 腾讯文档 / 金山文档 / Office/WPS 本地编辑 / PPT 生成 |
| 连接器生态 | 50+ 官方 MCP 连接器 + 自定义 MCP（GitHub、飞书、钉钉、金融、法务等） |
| 专家中心 | 100+ 领域专家，按分类发起专业对话 |
| 自动化 | 定时/周期任务（RRULE 或单次触发，支持有效期） |
| 任务管理 | 状态机（进行中/完成/失败/待处理/规划中/已归档）+ 置顶/分享/归档/继续处理 |
| 记忆与身份 | 三层记忆 + SOUL/IDENTITY/USER 身份文件 |
| 部署分发 | CloudStudio 静态站点一键发布 |
| 结果呈现 | present_files 产物卡片 + HTML 预览、Visualizer 内联图表 |

**三个核心判断**：① 从"对话产品"到"执行产品"的范式转移；② "办公"只是起点，边界被 50+ 连接器不断外扩；③ 功能深度依赖底层机制（框架/记忆/Skill）。

### 📖 分册 02 · Agent 框架解读（详见 `02-WorkBuddy-Agent框架解读.md`）

**Agent Loop 主循环**：分析上下文 → 思考规划 → 选择工具 → 执行 → 观察 → 迭代 → 结果呈现。模型负责推理，框架负责结构、秩序与安全。

**三种工作模式（自主程度调节旋钮）**：

| 模式 | 行为 | 适用 |
|---|---|---|
| Craft | 直接执行（You say, I do） | 常规任务，默认 |
| Plan | 先出方案、用户确认后执行 | 高成本/高风险任务 |
| Ask | 只读问答，不动文件不执行命令 | 咨询、澄清问题 |

**四级工具能力体系**：专用工具（Read/Write/Edit/Bash…）→ 延迟工具（ToolSearch 发现 + DeferExecuteTool 装配，控上下文成本）→ MCP 连接器 → Skill。权限模型 = **沙箱 + 高危操作升级授权 + 工具描述即文档**。

**并发与协作**：任务管理工具（TaskCreate/TaskUpdate）把隐性思考外化为结构化进度；子代理体系（general-purpose / Explore / Plan）支持并行与后台运行；团队协作（TeamCreate + 共享任务列表 + SendMessage）支撑多 Agent 群组编排。

**设计哲学三关键词**：自主执行、工具调度、进度可见——用户看到的不是一次生成，而是**可观察、可干预、可恢复的完整工作流**。

### 📖 分册 03 · 记忆技术解读（详见 `03-WorkBuddy-Agent记忆技术解读.md`）

**三层记忆 + 身份层**：

| 层 | 载体 | 作用域 | 关键特性 |
|---|---|---|---|
| 云记忆 | 服务端画像注入 `<memory>` 块 + conversation_search 历史检索 | 全局/跨项目 | 画像只读防漂移；检索需自包含查询 |
| 用户级本地 | `~/.workbuddy/MEMORY.md` | 跨项目 | 4000 字符/会话，显式写入 |
| Workspace | `{workspace}/.workbuddy/memory/`：日志 + MEMORY.md | 单项目 | 日志 append-only；笔记 3000 字符/会话；30 天归档 |
| 身份层 | SOUL.md / IDENTITY.md / USER.md | 全会话 | 决定"以什么姿态存在" |

**核心纪律**：
- **写入**：只记实质工作（建站/修 Bug/写报告/技术选型/约定）；瞬态信息与机密一律不记；
- **检索**：项目历史 → 读本地日志；跨项目/位置不确定 → conversation_search；无依赖 → 跳过；
- **边界**：记忆是信息（informational），Skill 是可执行工作流（actionable）。

**对架构师的启示**：agent 的记忆不是"把一切存下来"，而是"**在合适的层、以合适的成本、存值得存的信息，并在需要时以最小代价取回**"。

### 📖 分册 04 · Skill 调用技术解读（详见 `04-WorkBuddy-Skill调用技术解读.md`）

**一套机制**：以 SKILL.md（frontmatter + 指令正文）为载体的**五层技能体系**——用户级（`~/.workbuddy/skills/`，跨项目默认）/ 项目级（`{workspace}/.workbuddy/skills/`）/ 内置（builtin）/ 连接器配套 / 市场分发（BuiltinMarket）。

**两条原则**：
- **先加载后响应**：任务匹配技能即 BLOCKING 加载 SKILL.md 指令，强制按规程执行；
- **先搜索后放弃**：能力缺口必须先 find-skills 搜索，浏览器操作必须走 agent-browser。

**三个闭环**：
1. **生命周期闭环**：创建（skill-creator）→ 安全审计（skills-security-check：P0 强烈警告/P1 需确认/P2 放行）→ 反思修正（SkillManage，仅限 agent_created）；
2. **调用闭环**：任务 → 匹配 → 加载 → 执行 → 交付；
3. **资产闭环**：多步任务（8+ 工具调用）→ 沉淀为技能 → 复用 → 再沉淀。

**定位**：知识交给记忆，原子能力交给工具与 MCP，而"怎么做成事"的空隙由 Skill 填补——**把能力资产化、把资产流程化、把流程受控化**。
