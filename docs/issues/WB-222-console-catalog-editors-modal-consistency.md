## 问题

技能目录在 WB-219 中已改为“纯列表 + 新增/编辑弹窗”，但同一 Console 目录运营中心仍有多套旧交互：
连接器定义、知识库模板、技能推荐位把编辑表单常驻在列表上方，点击列表“编辑”后仅回填表单并滚到页首；
专家推荐位与连接器推荐位也把新增表单常驻列表页，且缺少编辑入口。

这让列表浏览、创建、编辑三种状态混在同一页面，长表单会持续挤压列表，且同一目录中心的操作方式不一致。

## 触发场景

进入 Console 的连接器或知识库“目录管理”、技能“推荐位管理”，点击任一列表项的“编辑”——页面滚回顶部并把数据填进常驻表单，而不是打开有明确保存/取消边界的编辑器。

## 影响

P2：数据功能可用，但随着目录项增多，列表浏览效率和编辑状态可辨识度持续下降；推荐位还存在只能删除重建、无法直接修改时间窗和排序的问题。

## 建议修法

- 目录列表页只保留标题、说明、“新增”按钮和数据列表。
- 连接器定义、知识库模板、专家/连接器/技能推荐位统一复用现有 `.np-*` 弹窗骨架进行新增和编辑。
- 从橱窗详情跳“编辑此项”时直接打开对应弹窗，不再把用户带到顶部常驻表单。
- 保留项目任务列表的状态/优先级等快捷内联编辑；那是高频单字段操作，不属于目录对象的多字段 CRUD 表单。

## 验证

- 五类目录 CRUD 列表均无常驻编辑表单；新增/编辑都打开弹窗，保存后刷新列表，取消不写入。
- 专家与连接器推荐位补齐编辑入口，可修改引用、时间窗和排序。
- 弹窗支持 ×、取消、遮罩与 Esc 关闭；明暗主题及窄宽下可读、无横向溢出。
- Console 脚本语法检查、`npx tsc --noEmit` 与 `npx vite build` 通过；真实 `:8100` 浏览器回归无 Console 错误。
