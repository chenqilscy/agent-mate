## 问题

现有自动化页在没有任务时直接返回独立空态，顶部“定时任务 / 运行记录”消失；有任务时模板库又被移到
独立子页面，导致同一个功能在空态和非空态的信息架构不一致。页面也没有形成参考设计中的
“顶部分页 → 当前状态/空态 → 自动化任务模板”稳定结构。

## 触发场景

删除最后一个自动化任务后进入自动化页，无法切换到历史运行记录；创建第一条任务后，首页模板区突然消失，
必须再点击“从模板添加”才能找到同一批模板。

## 影响

P2：真实调度、运行记录和模板创建能力都存在，但入口随任务数量改变，用户难以形成稳定认知；空态下还会
遮蔽已有历史记录。

## 建议修法

- 自动化主页始终展示“定时任务 / 运行记录”分页，不以任务数量决定页面骨架。
- 定时任务为空时展示居中引导和真实“添加自动化”按钮；有任务时展示现有真实列表、启停和操作菜单。
- 模板库固定放在定时任务页下方，模板点击继续进入现有编辑器并携带真实预填，不新增假模板动作。
- 使用既有 token 与组件，核对浅色、深色和窄屏三列模板的可读性与溢出。

## 验证

- 零任务时仍可切换运行记录；模板卡点击进入编辑器且名称/提示词已预填。
- 有任务时启停、立即运行、编辑、历史、删除能力不回归，模板区仍可见。
- 浅色/深色、宽屏/窄屏无不可读文字或水平溢出；类型检查和生产构建通过。

## 处理记录（2026-07-20）

- 移除“零任务时整页提前返回”，自动化主页始终保留“定时任务 / 运行记录”分页。
- 定时任务页按参考图改为居中空态、真实“添加自动化”按钮和下方三列模板；现有任务列表、启停和菜单不变。
- 模板仍来自真实目录，点击进入原编辑器；浏览器实测首个模板名称和提示词均正确预填。
- 真实本地数据下，零定时任务仍可切到运行记录并显示 100 条历史记录；模板目录显示 9 项。
- 浅色/深色宽屏截图通过，420px 时模板改为单列，水平溢出为 0。
- `npx tsc --noEmit`、`npx vite build`、`git diff --check` 通过。
