## 问题

AgentMate Manager（App 云端管理端，定位见 epic [WB-112](WB-112-manager-positioning-data-spec.md)）
当前左栏是一条**扁平混杂**的菜单（[console.html:326](../../hub/web/console.html#L326)）：
`项目 · 目录运营中心 · 组织 · 通知 · 设置`。作为一个云端 admin console，这套 IA 不专业：

1. **层级/颗粒度不齐**：把「项目」（操作型工作区）、「目录运营中心」（庞大管理域）、「组织」（实体管理）、
   「通知」（消息流）、「设置」（配置）平铺在同一层，它们不是同级概念。
2. **「目录运营中心」是塞满的筐**：内含 4 顶 tab（专家·专家团/连接器/技能/高级 JSON）× 每个再嵌
   2–3 子 tab（浏览橱窗/目录管理/SkillHub 同步）= 三层嵌套挤在一个菜单项，导航困难。
3. **内部术语外泄**：「目录运营中心」「SkillHub 同步」「高级 JSON」是实现/运营黑话；裸 JSON 编辑逃生口
   不该出现在正式导航。
4. **无分区**：应分「工作区 / 目录（内容分发）/ 系统」三类，现挤成一坨；「通知」通常是顶栏铃铛而非一级菜单。
5. **缺概览/仪表盘**：admin 首屏一般是总览（项目/成员/下发目录规模），现直接甩进项目列表。

## 触发场景

登录 Manager 控制台（平台管理员如 alice）→ 左栏五项平铺 + 「目录运营中心」三层嵌套 → 观感业余、找功能靠翻。

## 影响

P2：不阻塞功能（各页都在），但作为对外的 App 管理端，导航专业度直接影响产品可信度与可用性。

## 建议修法（目标 IA）

纯前端改 [console.html](../../hub/web/console.html)，沿用现有 token/class，不引入新视觉体系：

```
顶栏：  [组织切换 ▾]              🔔通知   alice · 平台管理员 ▾
──────────────────────────────────────────────
工作区
  概览 / 仪表盘        ← 新增（项目数/成员/下发目录规模等汇总）
  项目
  组织与成员           ← 合并原「组织」
目录（内容分发）        ← 「目录运营中心」重命名并提升为分区
  专家
  连接器
  技能                 ← SkillHub 同步/浏览橱窗收进「技能」内部
  · 高级 JSON 降级为各类目里的「高级」入口，不占一级
系统
  设置
```

- 侧栏分区（带小标题分组），把原 4 tab 提升为「目录」分区下的并列页。
- 「通知」移到顶栏铃铛（保留原 notifsView 内容，改从铃铛弹出/进二级）。
- 新增「概览」页：读现有 API 汇总（项目/组织/成员/目录条数），不造假（铁律#1）。
- 权限：目录/系统分区仍仅 `is_platform_admin` 可见（沿用 line 326 现有判断）。
- 续用防并发撞类名的前缀约定（如 `nv-` 导航层）；改动集中、避免与并发会话大范围冲突。
