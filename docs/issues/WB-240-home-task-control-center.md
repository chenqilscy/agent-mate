## 问题

首页当前只有场景快捷入口和 Composer。真实 session、自动化运行结果和消息 diff 已经持久化，
但首页没有汇总执行中、等待输入、近期自动化失败或带文件变更的最近交付；用户必须在侧栏、自动化页
和会话详情之间逐一查找，首页尚未承担路线图定义的任务控制台职责。

## 触发场景

用户打开 App 根页面，希望继续一个正在运行的任务、处理失败自动化或查看最近生成的文件；当前首页
没有任何状态入口，只能从长侧栏中手动定位。

## 影响

P1：用户难以及时发现需关注执行和已有交付，任务发起与任务完成被割裂，也无法形成 R0 的统一产品口径。

## 建议修法

- 首页基于真实 `SessionInfo.status/run_status` 汇总进行中、等待输入和 7 天内自动化失败；
- 对有限数量的最近完成会话读取持久化 trace，仅把真实 `diff.file` 聚合为最近交付；
- 状态与交付条目可直接打开原会话，项目会话回到项目执行页；
- 复用既有 token 与组件风格，明暗主题和窄屏都可用；不提前伪造独立 Run/Artifact 状态。

## 验证

- 首页展示的数量和条目均可由 `/api/sessions` 与会话消息 trace 核对；
- 点击普通、自动化或项目条目能打开正确会话；
- 无运行/失败/交付时展示诚实空态，后端不可用不阻塞任务输入；
- `pnpm test:regression`、`pnpm build` 通过；浏览器明暗主题与窄屏实测无回归。
