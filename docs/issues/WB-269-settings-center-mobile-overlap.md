## 问题

设置中心固定使用 `236px` 左侧导航与右侧内容双栏，`.set-modal` 只限制为 `96vw`，没有手机宽度的布局切换。约 420px 视口下右侧仅剩约 140px，个性化标题、说明、分段控件与风格卡片发生逐字换行和相互重叠。

## 触发场景

在 420px 左右的 App 窗口打开“设置中心 → 个性化”，切换浅色主题；设置导航占据大半宽度，右侧正文与控件无法正常阅读和操作。

## 影响

P1：设置中心是模型、助理、记忆、安全等关键配置的统一入口；小窗口下多个设置页实际不可用，并且与 WB-197、WB-202 已记录的窄屏通过结论发生回归。

## 建议修法

- 为设置中心增加手机断点：导航改为顶部/可收起入口，内容面板占满可用宽度，不能仅继续压缩双栏。
- 复用现有 token 与 Ant Menu/Modal 语义，不写死浅色背景；保持设置项切换与关闭焦点行为。
- 检查个性化、通用设置、模型管理等不同内容长度页面，避免单页特修。

## 验证

- 420px 与 640px 视口下导航和内容均可达，无横向溢出、逐字换行或重叠。
- 浅色、深色主题均正常；设置页切换、关闭与表单操作保持可用。
- `npx tsc --noEmit`、生产构建和相关 UI 回归通过。

## 处理记录（2026-07-21）

- 改动：在 `640px` 及以下将设置中心切换为上下布局，桌面 Ant `Menu` 收起为顶部 Ant `Select`，
  内容面板占满可用宽度；各分组与设置页仍使用同一份 `TAB_GROUPS` 数据，避免两套导航漂移。
- 改动：修复 Ant Button 默认固定高度和不换行规则对个性化风格卡片的覆盖，卡片改为内容自适应高度，
  保证标题与说明在窄屏下不会跨卡片重叠。
- 验证：在真实 `http://127.0.0.1:8102/` 页面以 429×642、640×760 验收账户、个性化和模型管理；
  明暗主题、页面切换与关闭均正常，Modal 与内容面板横向溢出均为 0，卡片内容无越界；验收后恢复深色主题、
  默认视口和根页面。
- 验证：`npx tsc --noEmit`、`pnpm build` 与
  `backend\.venv\Scripts\python.exe -m unittest backend.tests.regression.test_app_ant_design_migration`
  全部通过（6/6）。
