## 问题

Console 用逗号分隔的自由文本维护工具名，Server 不校验；App 运行时注册表目前只有少量精确名称，未知项会被 `_resolve_tools`
静默跳过。虽然界面文字提示“仅代码已注册的工具会生效”，但运营者仍无法知道可选项、拼写是否正确，以及不同 App 版本是否支持。

## 触发场景

在技能的工具名中填写 `web_feth` 或一个尚未注册的名字并保存。目录发布和下行均成功，运行时不报配置错误，技能只是悄悄少了工具能力。

## 影响

P2：技能看似配置完成但执行能力与运营预期不一致，错拼和版本不兼容只能在实际对话中发现。

## 建议修法

- 用可搜索多选控件替代自由文本，展示工具名、用途和最低 App 版本；来源字段改为系统生成或只读元数据。
- Server 保存时校验当前支持的工具契约；需要预发布未来工具时必须显式标为未就绪，不能与可用工具混在一起。
- App 下行/详情返回 resolved 与 unresolved 工具，Console 和 App 均能展示不兼容状态，运行时留下可观察告警。

## 验证

- 正常技能只能选择已注册工具；拼写错误不能保存，或以明确的“未支持”状态保存。
- App 详情和执行 trace 能区分已解析/未解析工具，不再静默降级。
- 不带工具的纯指令技能仍可正常创建和运行。

## 处理记录（2026-07-21）

- 改动：新增共享 `shared/skill-tools.json` 工具契约，Server 暴露只读工具目录并拒绝未知工具；Console 自由文本改为带用途和最低版本的多选项，来源改为系统只读。
- 验证：真实页面显示 4 个注册工具并可选择；Server 拒绝 `web_feth`，回归门禁确认共享契约与运行时 `_TOOL_REGISTRY` 名称完全一致，纯指令技能仍可保存。
