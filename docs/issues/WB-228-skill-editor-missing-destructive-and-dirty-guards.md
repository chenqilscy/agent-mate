## 问题

技能列表点击“删除”会立即发起 DELETE，没有二次确认；弹窗中修改基本信息或文件后，点击关闭、取消或遮罩会直接丢弃，
没有 dirty 提示。文件级删除反而已有 `confirm`，整项删除的保护更弱。保存期间按钮也未锁定，可能重复提交。

## 触发场景

- 在目录管理列表误点任意技能的“删除”，条目立即消失。
- 打开新增/编辑弹窗，修改名称、指令或文件，点击右上角关闭或遮罩，内容无提示丢失。

2026-07-21 浏览器实测：临时技能整项删除没有确认弹窗；填写未保存内容后点击关闭也没有警告。

## 影响

P2：运营数据可因一次误点被删除，长指令和多文件编辑可能无提示丢失；操作风险与编辑成本不匹配。

## 建议修法

- 整项删除使用明确的危险确认，展示技能名称、slug、推荐/安装影响；优先提供停用而非删除。
- 统一追踪基本信息和文件 dirty 状态；关闭、取消、遮罩和 Escape 走同一离开保护。
- 保存/删除请求期间禁用相关按钮并显示进行中状态，避免重复提交。
- 完善 dialog 的初始焦点、焦点圈与键盘行为，label 与表单控件建立关联。

## 验证

- 删除需二次确认，取消不发请求；确认后成功或失败都有明确反馈。
- 任意字段/文件改动后离开会提示，未改动可直接关闭；保存成功后不再提示。
- 快速双击保存/删除只产生一次请求，键盘操作与明暗主题均可用。

## 处理记录（2026-07-21）

- 改动：基本信息与文件统一 dirty 指纹，取消/关闭/遮罩/Escape 均走放弃确认；保存、启停、归档和排序请求期间禁用按钮。整项删除改为带影响说明的确认归档，后端同时保证不物理删除。
- 验证：UI 契约覆盖离开保护、进行中状态与归档入口；浏览器验证必填拦截、保存关闭与明暗主题，Server 验证归档保留身份。
