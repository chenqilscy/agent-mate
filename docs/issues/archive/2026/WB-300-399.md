## WB-300 · 终态 issue 归档后正文相对链接失效且校验漏报

<details>


</details>

### 问题

`scripts/archive_issues.py` 归档终态 issue 时会把正文从 `docs/issues/` 移入
`docs/issues/archive/<year>/`，但 `render_record` 保留了正文中的普通相对链接，
`rewrite_issue_links` 又只处理指向已知 issue 文件的链接。原先从 `docs/issues/`
出发的 `../../src/...`、`../agentmate-*.md` 等链接因目录层级变化而失效。

现有 `validate` 也只检查已知 issue 文件名，因此 `--check` 在归档正文存在大量失效链接时仍返回成功。

### 触发场景

打开任意包含源码或设计文档引用的历史 issue，例如归档卷
`docs/issues/archive/2026/WB-001-099.md`，点击正文中的 `../../src/...` 链接；
解析目标会落到 `docs/issues/src/...`，而不是仓库根的 `src/...`。

### 影响

终态 issue 是缺陷处理与验证证据的审计记录。链接失效会阻断从问题描述、处理记录到源码证据的追溯，
且校验漏报使后续每次归档继续固化错误。

### 建议修法

- 为归档记录引入明确格式版本。
- 新归档记录把普通相对链接从原 issue 路径重定位到归档卷路径。
- 对旧格式记录执行一次确定性迁移，避免重复运行时二次改写。
- 增加归档格式/幂等回归测试，并让 `--check` 拒绝未迁移记录。

### 验证

- 对现有 297 条归档记录执行迁移后，源码与当前设计文档链接解析到仓库中的正确目标。
- `python scripts/archive_issues.py --apply` 连续运行两次无第二次内容变化。
- `python scripts/archive_issues.py --check` 通过，并能识别未迁移的旧格式记录。

### 处理记录（2026-07-23）

- 为归档记录加入 `archive_format=2`，新旧记录统一按源文件与目标卷路径重定位普通相对链接；
  校验会拒绝未迁移格式，旧卷迁移仅执行一次。
- 新增 2 条回归，覆盖新记录重定位和旧格式迁移幂等性；现有 297 条归档记录已完成迁移，
  连续两次执行 `--apply` 内容不再变化。
- 验证：归档回归 2/2、Backend regression 149/149、`--check`、`py_compile` 均通过。
- commit：待本次自动审查提交。

## WB-301 · 中央知识库上传在异步路由中阻塞 Server 事件循环

<details>
<summary>原始元数据</summary>

```yaml
id: WB-301
title: 中央知识库上传在异步路由中阻塞 Server 事件循环
severity: P1
area: backend
status: fixed
origin: 🆕 近期改动
files:
  - server/routers/knowledge.py:371
  - server/routers/knowledge.py:393
created: 2026-07-23
```

</details>

### 问题

`server/routers/knowledge.py::upload_document` 是异步路由，流式读取请求体后直接调用同步的
`weknora.upload_file`。该客户端内部使用 `httpx.request(timeout=60)`，因此上游慢请求会在
Server 主事件循环线程中同步等待。

同类本地 backend 知识库路由已使用 `run_in_threadpool`，Server 新增的中央知识库路径遗漏了该边界。

### 触发场景

成员向中央项目知识库上传文件，同时 WeKnora 响应缓慢或网络超时；上传路由在同步 HTTP 调用期间
占住事件循环，其他账号的健康检查、项目协作和 Console 请求不能及时调度。

### 影响

单个合法上传即可造成最长约 60 秒的 Server 全局响应冻结。多人协作或 WeKnora 异常时会放大为
控制平面可用性问题，因此按 P1 处理。

### 建议修法

把同步 `weknora.upload_file` 调用移到工作线程，同时保留请求体流式上限、权限检查、错误映射和
返回契约。增加回归测试，断言上游调用线程与异步路由线程不同。

### 验证

- 定向测试确认 `weknora.upload_file` 不在事件循环线程执行。
- 成员上传返回契约不变，Viewer 仍被拒绝。
- Server 全量测试、Python 编译与集成测试通过。

### 处理记录（2026-07-23）

- 用 `run_in_threadpool` 执行同步 `weknora.upload_file`，请求体上限、角色门禁、错误映射和响应契约保持不变。
- 回归测试记录路由线程与上游调用线程，确认二者不同，同时保留 Viewer 只读断言。
- 验证：Server 63/63、Backend integration 2/2、Python 编译均通过。
- commit：待本次自动审查提交。

## WB-302 · 中央知识库后续分页文档无法通过归属校验并删除

<details>
<summary>原始元数据</summary>

```yaml
id: WB-302
title: 中央知识库后续分页文档无法通过归属校验并删除
severity: P2
area: backend
status: fixed
origin: 🆕 近期改动
files:
  - server/routers/knowledge.py:453
created: 2026-07-23
```

</details>

### 问题

删除中央 WeKnora 文档前，Server 为防止跨知识库删除，会调用
`weknora.list_docs(..., page_size=500)` 检查 `doc_id` 是否属于目标知识库。但实现只读取第一页。
目标库超过 500 条文档时，后续页的合法文档会被误判为不存在。

### 触发场景

项目知识库已有 500 条以上文档，成员在 Console 删除第 501 条或更后的文档；
Server 只检查第一页并返回 404，文档无法删除。

### 影响

大型项目知识库的文档生命周期不完整，且不能通过取消归属校验来规避，否则会允许持有其他库文档 ID
的成员跨库删除。

### 建议修法

保留稳定知识库 ID → provider ID 的授权边界，按 WeKnora 返回的 `total` 分页查找目标文档；
找到后才删除，遍历结束仍未找到则返回 404。增加跨页找到与不存在两条回归。

### 验证

- 模拟目标文档位于第二页，确认会继续请求并成功删除。
- 模拟全部分页均不含目标文档，确认返回 404 且不调用删除。
- Server 全量测试与 Python 编译通过。

### 处理记录（2026-07-23）

- 新增知识库内文档归属分页检查，按 `total` 逐页读取，每页 500 条；只有目标文档确属当前
  provider 知识库时才调用删除。
- 新增第二页命中和跨库/不存在拒绝两条回归，后者确认不会调用 provider 删除接口。
- 验证：Server 63/63、Python 编译均通过。
- commit：待本次自动审查提交。

```yaml
  - console/src/SkillsPage.tsx:261
created: 2026-07-23
```

</details>

### 问题

运行服务设置直接使用 Ant Design 已弃用的 `List`，并给 `Alert` 传入已弃用的 `message` 属性；
技能兼容告警和 Console 多个页面也仍使用 `Alert.message`。在当前 Ant Design 6.5.1 下，打开对应界面会向浏览器错误日志
输出弃用告警，`List` 还明确标记为下个主版本删除。

仓库已有 `CompatList` 作为兼容封装，但新设置页未复用。

### 触发场景

打开 App「设置中心 → 运行服务」，浏览器控制台出现：

- `[antd: Alert] message is deprecated. Please use title instead.`
- `[antd: List] The List component is deprecated.`

打开不兼容技能详情时还会再次触发 `Alert.message` 告警。

### 影响

真实错误日志被兼容性噪声污染，影响前端验收和故障观察；后续升级 Ant Design 主版本时，
运行服务审计列表会直接失去组件支持。

### 建议修法

设置页复用仓库既有 `CompatList`，App 与 Console 的 `Alert` 改用当前 `title` 属性，保持现有 class、主题与文案不变。

### 验证

- `pnpm build` 通过。
- 浏览器打开运行服务设置，明暗主题均正常，错误/警告日志不再出现上述弃用信息。
- App 与 Console 源码不再给 `Alert` 使用 `message`。

### 处理记录（2026-07-23）

- App 运行服务列表改用既有 `CompatList`，App 与 Console 全部 JSX `Alert.message`
  改为 Ant Design 6 的 `title`，文案、class 与主题 token 不变。
- 源码扫描确认两端不再存在 JSX `message=`，也没有直接导入 Ant Design `List`。
- 验证：App + Console 生产构建通过；App 运行服务页完成明暗主题检查；最新 Console
  平台设置、项目列表与项目详情真实页面正常，双方浏览器 error/warning 日志均为空。
- commit：待本次自动审查提交。
