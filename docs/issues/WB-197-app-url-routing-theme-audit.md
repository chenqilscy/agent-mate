## 问题

当前 `App.tsx` 用 `uiStore.view` 的 `switch` 在同一 URL 下切换全部功能页，
`setView` 只改内存状态，不更新浏览器地址。项目、知识库、自动化等页面不能复制链接、
刷新后回到首页，浏览器前进/后退也无法表达页面导航。现有主题规则经历多轮局部补丁，
多页化后还需要逐页核对浅色/深色表面、文字、边框和交互态。

## 触发场景

从侧栏进入“项目”或“知识库” → 地址栏始终不变；刷新或使用浏览器后退 → 无法回到对应页面。
切换深色主题逐页浏览时，部分硬编码浅色表面只能靠零散选择器覆盖，缺少覆盖检查。

## 影响

P1：顶层信息架构没有真实页面边界，无法深链、恢复和使用浏览器导航；主题回归只能人工碰运气，
随着页面增加容易再次出现浅底浅字或深底深字。

## 建议修法

- 建立无额外依赖的 URL 路由层，为首页、对话、项目、自动化、专家/技能、知识库、文件等顶层页面提供稳定路径。
- `setView` 保持现有调用兼容，同时同步 History API；监听 `popstate`，首次启动按 URL 恢复页面，未知路径安全回首页。
- 项目/会话详情路径携带资源 ID，刷新时按权限重新加载，不依赖上一次内存对象。
- 新增的页面/路由状态只使用既有 token；逐页核对浅色/深色和窄宽布局，修复审查中确认的对比度问题。

## 验证

- 每个侧栏顶层入口都有稳定 URL；直接打开、刷新、前进/后退均落到正确页面。
- 项目详情和执行会话的深链能重新加载资源；无权或不存在时安全退回列表。
- `npx tsc --noEmit`、`npx vite build` 通过。
- 浏览器实测主要页面的浅色/深色两套主题，并在窄宽下检查导航、设置页和项目配置无溢出、无不可读文本。
