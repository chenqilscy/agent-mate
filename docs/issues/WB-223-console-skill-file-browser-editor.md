## 问题

WB-219 已让技能定义能够携带真实文本文件，但 Console 的“文件”页仍是扁平文件行列表，编辑表单固定堆在列表下方。
嵌套路径不会呈现为目录树，选择文件与编辑内容之间也没有清晰的主从关系；自动生成的 `SKILL.md` 只能看到一行说明，不能预览实际内容。

## 触发场景

打开 `/catalog/skills` → 目录管理 → 新增或编辑技能 → 文件。当技能包含 `references/guide.md`、
`templates/report.md` 等多个嵌套文件时，只能在一串扁平行中逐个点“编辑”，再滚到下方表单，无法像文件工作区一样浏览和连续编辑。

## 影响

P2：文件存储与安装能力真实可用，但多文件技能的维护效率低，目录结构难以理解，容易编辑错文件。

## 建议修法

- 文件页改为左侧文件浏览器、右侧文件编辑器；浏览器按相对路径生成可折叠目录树并支持搜索。
- 选中文件后在右侧直接编辑路径和 UTF-8 内容；新增、应用更改、删除都围绕当前文件操作。
- `SKILL.md` 作为根文件显示，内容按真实安装格式实时生成并只读预览；提供“编辑技能指令”快捷入口。
- 继续复用 WB-219 的 files 数据模型、路径安全校验、128 文件与 1MB 限制；不持久化空目录。

## 验证

- 多级路径正确形成目录树，目录可折叠，搜索能过滤文件；选择不同文件时右侧内容准确切换。
- 新建、改路径/内容、删除后保存技能并重新打开，树与内容均持久化；取消不写入。
- `SKILL.md` 预览与 App 安装目录技能时生成的格式一致，基本信息或指令变化能实时反映。
- Console 脚本语法、UI 契约测试、`npx tsc --noEmit`、`npx vite build` 与真实 `:8100` 浏览器回归通过。

## 处理记录（2026-07-21）

- 改动：技能“文件”页升级为左侧文件浏览器、右侧文件编辑器；相对路径自动形成多级可折叠目录树，支持文件搜索、新建、选择、改路径/内容、撤销、应用与删除。`SKILL.md` 按 App 安装目录技能的真实格式实时生成，只读预览并可跳转编辑技能指令；继续复用原 files 存储与 Server 安全校验。
- 验证：Console 脚本语法、4 项 UI 契约与 5 项技能目录测试共 9 项通过；`npx tsc --noEmit`、`npx vite build` 通过。真实 `:8100` 创建临时技能与 `references/guide.md`、`references/api/schema.md`，保存后重新打开目录树和内容一致；再将文件内容从 `version: 1` 改为 `version: 2`，保存并重开确认持久化。搜索、目录折叠、连续切换自动应用均通过，两个临时技能均已删除清理。
