## 问题

`src/App.tsx` 始终在应用内容上方渲染高 32px 的 `MenuBar`。此前只移除了“编辑(E)”“窗口(W)”“帮助(H)”三个文字菜单，仍保留应用标识、空白拖拽区和窗口按钮，未满足“把 menubar 这一整行都去掉”的原始意图。

## 触发场景

打开 WorkBuddy 浏览器端或桌面端，页面内容上方始终存在一整行 `.menubar`，占用 32px 垂直空间。

## 影响

顶部整行占用额外垂直空间，且应用标识与侧栏头部重复，削弱界面简洁度；不影响核心功能，定为 P3。

## 建议修法

从应用外壳移除整个 `MenuBar` DOM 及其样式，不再保留应用标识或最小化、最大化、关闭按钮。把窄屏打开侧栏、宽屏恢复已收起侧栏的入口改为独立浮动按钮，避免导航死路。

## 验证

- DOM 中不再存在 `.menubar`，应用内容从窗口顶部开始。
- WorkBuddy 顶部标识及最小化、最大化、关闭按钮随整行移除。
- 宽屏收起侧栏后、窄屏隐藏侧栏时仍有独立入口可恢复导航。
- 宽屏和窄屏布局均无异常，明暗主题通过，前端类型检查与生产构建通过。

## 处理记录（2026-07-20）

- 改动：从 `src/components/layout/MenuBar.tsx` 删除“编辑(E)”“窗口(W)”“帮助(H)”及其专属更新检查逻辑，并清理 `src/styles/app.css` 中不再使用的 `.mb-menu` 样式；保留应用标识、拖动区域、响应式侧栏入口和窗口控制。
- 验证：`npx tsc --noEmit`、`npx vite build`、`git diff --check` 通过；浏览器实测 1440×900 明暗主题与 800×700 窄窗口，文字菜单数量为 0，窗口控制数量为 3，窄屏侧栏按钮可见且横向溢出为 0。
- commit：本次菜单与设置功能优化提交（见 Git 历史）

用户通过 DOM 截图明确指出目标是移除整个 `.menubar` 32px 行，而非只删除其中三个文字菜单；本 issue 因验收范围理解偏差重新打开处理。
