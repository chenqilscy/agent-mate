## 问题

`src/components/layout/MenuBar.tsx` 在应用自绘标题栏中固定展示“编辑(E)”“窗口(W)”“帮助(H)”三个文字菜单。其中编辑和窗口没有任何交互，帮助仅承载检查更新，与当前设置中心的信息架构重复。

## 触发场景

打开 WorkBuddy 浏览器端或桌面端，标题栏左上角应用名称后始终出现“编辑(E)”“窗口(W)”“帮助(H)”。

## 影响

顶部占用额外横向空间，展示了不可用或重复的入口，削弱界面简洁度；不影响核心功能，定为 P3。

## 建议修法

从 `MenuBar` 移除三个文字菜单及其只为帮助菜单服务的更新检查逻辑，保留应用标识、响应式侧栏按钮和最小化、最大化、关闭窗口控制。

## 验证

- 顶部不再出现“编辑(E)”“窗口(W)”“帮助(H)”。
- WorkBuddy 标识及最小化、最大化、关闭按钮仍存在。
- 宽屏和窄屏布局均无异常，前端类型检查与生产构建通过。

## 处理记录（2026-07-20）

- 改动：从 `src/components/layout/MenuBar.tsx` 删除“编辑(E)”“窗口(W)”“帮助(H)”及其专属更新检查逻辑，并清理 `src/styles/app.css` 中不再使用的 `.mb-menu` 样式；保留应用标识、拖动区域、响应式侧栏入口和窗口控制。
- 验证：`npx tsc --noEmit`、`npx vite build`、`git diff --check` 通过；浏览器实测 1440×900 明暗主题与 800×700 窄窗口，文字菜单数量为 0，窗口控制数量为 3，窄屏侧栏按钮可见且横向溢出为 0。
- commit：本次菜单与设置功能优化提交（见 Git 历史）
