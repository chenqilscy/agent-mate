# AgentMate 能力完成度评估（2026-07-22）

> 评估对象：`D:\work\local\buddy` 当前 `master` 工作树（含本轮 WB-285～288 优化）。  
> 评估口径：代码与持久化模型、自动化测试、生产构建、实时 API、App/Console 浏览器页面共同成立；

## 1. 结论

AgentMate 已经是可真实执行、可持久化、可协作、可验收的 local-first AI 工作系统，不再是聊天原型。
按当前产品边界综合完成度评估为 **89/100（核心可用，生产运营仍有外部条件与深水区）**。

| 评估域 | 完成度 | 结论 |
|---|---:|---|
| 基础能力 | 91% | Run/Artifact、文件与 Office、浏览器、知识库、Skill/MCP、模型、安全与桌面壳已形成真实底座 |
| 助理 | 87% | 多助理、独立配置、App 对话、Telegram/邮件真实渠道和账户隔离可用；高可用与更多渠道仍受边界限制 |
| 项目管理与人员协调 | 92% | 角色、邀请、评论、通知、看板/列表/负载/甘特、里程碑、Sprint、度量和导出完整 |
| 任务执行与监控统计 | 88% | WorkItem→Run→Artifact→验收、自动化重试/DLQ和统一 owner 运营摘要已闭环；组织级实时运营仍可深化 |

评分不是代码覆盖率，而是“用户能否从目标发起一直走到可验证交付”的产品完成度。正式桌面更新生产部署
仍依赖公开 HTTPS、受保护签名材料、可信 Windows 代码签名证书与发布窗口，保持在 WB-283 deferred，
不把外部条件伪装成已经上线。

## 2. 基础能力评估

### 2.1 已完成

- **任务执行内核**：Session 与 Run 分离；Run 有明确生命周期、权限快照、检查点、错误、token、耗时和
  工具调用计数；Artifact 持久化路径、hash、校验、预览与验收状态。
- **真实工具**：项目沙箱内的文件读写/改名/移动/删除、命令执行、Office/PDF 产物、浏览器工具、
  知识库写入与检索均有真实实现和回归，不以提示词或目录卡代替工具。
- **能力系统**：专家、Skill、连接器、知识库和模型均有后端权威状态；Skill release、权限、兼容、
  tombstone、安装快照和本机实现交集已经建立。
- **Local-first 与安全**：LLM/渠道凭据留在本机 backend；Server 只管理控制平面与允许同步的元数据；
  文件沙箱、Viewer 只读、命令审计、secret 环境剔除和多用户资源门禁已经落地。
- **交付形态**：React App、FastAPI backend、可选 Server/Console、Tauri 2 + sidecar + updater 链路均存在；
  当前生产构建通过。

### 2.2 部分完成或边界

- `run_command` 是受限并审计的本机进程执行，不是 VM/容器级强隔离。
- 第三方连接器的真实可用性仍取决于用户凭据、外部服务与网络；不可用类型必须继续诚实标记。
- 正式桌面更新部署是唯一活动 deferred 项，代码与一次性签名演练已完成，但生产基建尚未提供。
- 本次会话未暴露 codebase-memory MCP 图查询接口，结构审计按仓库规则降级为源码/路由/测试检索；
  因此本报告不声称完成了知识图谱级调用链覆盖。

## 3. 助理完成情况

### 3.1 已完成

- 可创建多个助理，每个助理独立保存名称、头像、指令、模型、模式、工作空间和 loadout。
- App 内对话与外部渠道共用真实 agent runtime，不存在静态回复脚本。
- Telegram 与邮件具备真实入站、出站、绑定/白名单、offset/幂等、自回复防护和错误恢复路径。
- 渠道管理显示真实 enabled/running/token/binding 状态；未实现渠道不会展示假成功开关。
- 本轮 WB-285 已把全部助理/渠道 API 从固定 `LOCAL_USER` 改为当前鉴权 owner；双用户回归确认列表、
  详情、更新和渠道操作互相隔离。
- 首页统一运营摘要展示助理渠道异常数，避免只能进入单个助理后逐一检查。

### 3.2 部分完成或边界

- ChannelManager 随本机 backend 生命周期运行，依赖本机在线、电源与网络，不是独立高可用消息平台。
- 企业微信、WhatsApp 等未完成真实授权、收发、幂等和防循环前保持不可用；这属于诚实边界。
- 助理运营仍可继续扩展到单助理成功率、响应时延、渠道投递率和失败原因趋势；当前统一摘要先覆盖
  渠道健康和全局 Run 指标。

## 4. 项目管理、人员协调、任务执行与统计

### 4.1 项目管理

- 项目概览、计划、任务、负载、甘特、资产与讨论入口均可用。
- 工作项支持状态、优先级、负责人、日期、标签、父子任务、里程碑、工时、依赖、Sprint 和自定义字段。
- 具备看板、列表、WIP、泳道、保存视图、模板、批量操作、关键路径、燃尽和 CSV 导出。
- Console 项目概览以真实任务数据计算总数、进行中、完成、逾期、整体进度、里程碑和近期活动。

### 4.2 人员协调

- Server 是账号、组织、项目成员与角色的权威源；Owner/Admin/Member/Viewer 门禁覆盖读写。
- 邀请、成员增删改角色、评论、@提及、通知、在线状态与团队时间线已形成协作链路。
- App 对 server-origin 项目使用代理写入和本地镜像回退，避免下次 pull 静默覆盖本地修改。

### 4.3 任务执行与监控

- 工作项可直接发起本地 Run，使用幂等键避免重复执行；失败、取消和暂停可形成关联 retry Run。
- Run 产出的 Artifact 可在工作项交付面查看、校验与验收；全部产物通过后 Run accepted、工作项 done。
- 自动化有超时、token 上限、持久化重试、进程重启恢复、DLQ、重放/忽略、失败与恢复通知。
- 本轮 WB-286 新增 `/api/ops/summary`，统一聚合近 7 天 Run 成功率、失败、平均耗时、token、工具调用、
  待验收 Artifact、自动化 DLQ、逾期工作项和助理渠道健康；首页每 15 秒在可见状态刷新。
- 首页最近交付改读 Artifact manifest，不再对最近 12 个会话逐个读取 messages 并扫描 diff trace。

### 4.4 统计能力边界

- App 当前提供 owner/可访问项目范围的执行统计，Console 提供项目 PM 与目录发布统计；两者遵循
  “正文与文件不上云”的数据边界。
- Server 尚未保存足够的组织级 Run 明细，因此不能在 Console 做完整跨设备执行成本/质量趋势；若后续
  增加，只能同步明确允许的聚合元数据，不能突破 local-first 隐私红线。
- 目录 revision 仍依赖显式/低频 pull，没有实时推送失效信号；这不影响当前任务执行，但影响运营时效。
